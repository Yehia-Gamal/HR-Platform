# 08 — Android Device QA (P2)

**التاريخ / Date:** 2026-07-14
**الحالة / Status:** ⛔ **BLOCKED** — لا يوجد جهاز Android فعلي أو محاكي متصل في هذه البيئة.

---

## السبب

`flutter devices` يُظهر فقط: `Windows (desktop)`, `Chrome (web)`, `Edge (web)`.
لا يوجد جهاز Android حقيقي متصل، ولم يُشغَّل أي محاكي (emulator).

## ما لا يمكن إثباته هنا (يتطلب جهازًا فعليًا)

اختبارات P2.2 على جهاز Android حقيقي منخفض/متوسط/حديث الإمكانات:
- تسجيل الدخول بالبريد/الهاتف/كود الموظف + استعادة الجلسة.
- إبطال الجهاز ومنع دخوله + التحديث الإجباري + وضع الصيانة.
- **Passkey registration** (WebAuthn على العتاد الآمن للجهاز).
- Check-in/Check-out عبر Passkey.
- **GPS** داخل/خارج نطاق 300 متر، دقة ضعيفة، رفض Mock Location.
- **الكاميرا**: فيديو تحقق 5 ثوانٍ (دورة حياة الكاميرا).
- طلب الموقع الحي من المدير التنفيذي + انتهاء جلسة التتبع.
- **Push Notifications + Deep Links** (انظر 11).
- Offline ثم Sync دون تكرار (idempotent).
- ظهور الشاشات حسب الدور فقط.

## المطلوب لفكّ الحظر

1. جهاز Android فعلي (أو محاكي) متصل عبر ADB، أو Firebase Test Lab / جهاز سحابي.
2. تثبيت Debug APK (يُبنى محليًا — انظر `07_FLUTTER_ANALYZE_TEST_BUILD.md`).
3. Supabase Staging + الأسرار (Passkey RP ID, Push provider) — انظر 10 و11.
4. تسجيل Screenshots وLogs دون بيانات حساسة/PII حقيقية.

> لم تُزيَّف أي نتيجة. هذه بوابة خارجية تتطلب عتادًا غير متوفر في بيئة التشغيل الحالية.
