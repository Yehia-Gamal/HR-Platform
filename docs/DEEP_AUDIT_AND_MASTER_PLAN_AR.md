# الفحص العميق وخطة التنفيذ المحكمة — تحويل المنصة إلى نظام HR حقيقي كامل متكامل

**التاريخ:** 2026-07-14
**النطاق المفحوص:** 45 Migration، 26 اختبار pgTAP، 9 Edge Functions، تطبيق React Web (32 صفحة)، تطبيق Flutter (67 ملف Dart)، المواصفة V8، الحوكمة وCI/CD.

---

## الجزء الأول — نتائج الفحص العميق

### 1. تقييم عام

المشروع **ليس Vaporware** — البنية المعمارية حقيقية وناضجة:

- Backend: 45 Migration متسلسلة، ~207 دالة SQL، RLS/ABAC، RPC-first، SECURITY DEFINER منضبط.
- Flutter: 38 من ~40 صفحة حقيقية بالكامل (WebAuthn/Passkey فعلي، GPS فعلي، كاميرا فعلية، RPC-only).
- Web: 32 صفحة، أغلبها CRUD/Workflow حقيقي، صلاحيات مرتبطة بالخادم وليست ثابتة في الكود.
- التوثيق صادق بدرجة نادرة: البنود المعطلة معلنة BLOCKED ولا توجد ادعاءات مزيفة.

لكنه **غير جاهز إنتاجيًا** لثلاثة أسباب جوهرية:

1. **بوابة التشغيل لم تُغلق:** pgTAP لم يُعَد تشغيله نهائيًا بعد إصلاحات 0043/0045، بناء APK فاشل (Gradle)، لا Staging، لا اختبارات أجهزة فعلية، لا Backup/Restore.
2. **نواقص وظيفية تمنع تسميته HR كامل:** لا محرك رواتب حسابي، لا شاشة إدارة إجازات، لا Push Notifications، لا Offline للحضور الميداني، لا محرك تقارير.
3. **ثغرات أمنية تشغيلية:** لا كشف GPS مزيف، اختبارات Persona RLS غير منفذة، لا مراقبة أخطاء إنتاجية.

#### 2.2 تطبيق الويب (React)

- **حقيقي:** Recruitment (الأنضج)، Organization chart CRUD، Disputes، KPI Cycles، Lifecycle، Access/RBAC، Attendance Operations، Requests، Live Location.
- **قراءة فقط / Stub:** `PeopleFinancePage` (الرواتب معطلة صراحة)، `ReportsPage` (تصدير CSV فقط)، `SystemPage` (أعلام ميزات غير قابلة للتبديل)، `ActionCenterPage` (مقياس ثابت = 0)، `EnterpriseManagementPage` (بلا أي mutation).
- **مفقود كليًا:** شاشة إدارة إجازات مخصصة، دليل موظفين مستقل، محرك تقارير/تحليلات، ربط مراقبة أخطاء (Sentry)، نظام Toast، توحيد التحقق من النماذج (zod في صفحة واحدة فقط + `window.prompt()` في عمليات حساسة).

#### 2.3 تطبيق Flutter

- **حقيقي:** حضور Passkey+GPS+فيديو 5 ثوانٍ، تسجيل دخول متعدد المعرفات، طلبات/KPI/مهام/فريق/قرارات (~60 RPC)، حوكمة إصدار kill-switch.
- **الفجوات العشر الحرجة:**
  1. لا Push Notifications (لا firebase_messaging؛ `p_push_enabled: false` مضمّنة).
  2. لا كشف GPS مزيف (`Position.isMocked` غير مقروء؛ `isMock=false` دائمًا) → تزوير حضور ممكن.
  3. لا Offline إطلاقًا — بصمة حضور بلا إنترنت تضيع.
  4. لا تتبع موقع بالخلفية — جلسات التتبع تتوقف عند طي التطبيق.
  5. Deep links أندرويد فقط وبلا التقاط فعلي داخل التطبيق.
  6. الإشعارات جلب لمرة واحدة — لا Realtime ولا Polling.
  7. الاختبارات شكلية: 19/20 مجرد fromJson.
  8. أخطاء خام (`toString()`) تُعرض للمستخدم؛ فشل الشبكة عند الدخول صامت.
  9. لا قفل بيومتري للتطبيق (local_auth).
  10. 4 من 7 أدوار بلا تجربة موبايل (HR/أدمن/لجان/ميداني → صفحة مسدودة).

#### 2.4 الحوكمة وCI/CD

- 5 GitHub Workflows مكتوبة لكن **لا دليل على أي تشغيل CI فعلي**.
- توقيع Android غير متحقق، لا AAB موقّع، iOS بلا codesign.
- لا بيئات Dev/Staging/Prod فعلية، لا Observability، لا Backup/Restore drill.
- ملفات runtime-evidence مُشار إليها وغير موجودة (03–06، 08–12).
- تناقض حوكمي: شرط "لا واجهات قبل Persona RLS Tests" في BUILD_MASTER خُرق — الواجهات بُنيت والاختبارات لم تُنفذ.

### المرحلة 2 — استكمال نواة HR الحقيقية 🟡

هذه المرحلة هي الفارق بين "منصة عمليات" و"نظام HR كامل".

**2.1 محرك الرواتب (الأكبر):**
- Backend: `calculate_payroll_run(period)` — يجمع: الراتب الأساسي + البدلات (salary_components) + أثر الحضور (خصومات تأخير/غياب من فترات الحضور المغلقة) + الإضافي + أقساط القروض (loan_installments) + الضرائب/التأمينات حسب قواعد قابلة للضبط → توليد payslips/payslip_lines.
- دورة حالة: Draft → Calculated → HR Review → Finance Approval → Closed → (قفل الفترة، لا تعديل إلا بقيد تصحيحي).
- Web: شاشة تشغيل الدورة، مراجعة الفروقات مقابل الشهر السابق، اعتماد ثنائي (HR + Finance)، تصدير بنكي CSV.
- Mobile: عرض قسيمة الراتب للموظف (get_my_payslips موجودة).
- pgTAP: حالات حساب كاملة (موظف كامل الشهر، منضم منتصف الشهر، خصومات، قرض).
- **يبقى Feature-flag معطلًا في Production حتى اعتماد HR/Finance/Legal (كما تنص الحوكمة الحالية).**

**2.2 إدارة الإجازات المكتملة:**
- أتمتة الاستحقاق الشهري عبر Cron (البنية الدفترية موجودة في 0026).
- Web: شاشة إدارة إجازات مخصصة — أرصدة الفريق، الاعتمادات، التقويم، الترحيل السنوي (carryover)، سياسات الأنواع.
- تقرير تعارض الإجازات مع الروستر.

**2.3 الحضور المتقدم:**
- قواعد الإضافي (Overtime) والتأخير قابلة للضبط لكل موقع/وردية.
- الإغلاق الشهري يغذي الرواتب مباشرة.

**2.4 محرك التقارير:**
- مولّد PDF خادمي (Edge Function + قالب) للتقارير المجدولة — يغلق الـ stub الوحيد في Flutter (`executive_reports_page`).
- لوحة تحليلات HR: Headcount، Turnover، معدلات الحضور، توزيع KPI — Views مادية + شاشة ويب.

**2.5 استكمال الويب:**
- دليل موظفين مستقل (Directory) ببحث وفلاتر وبطاقات.
- توحيد النماذج: react-hook-form + zod في كل النماذج، إلغاء `window.prompt()`، نظام Toast موحد.
- تفعيل مقياس Action Center الحقيقي وأعلام SystemPage القابلة للتبديل (RPC موجودة الحاجة لربطها).

**2.6 تجربة موبايل للأدوار المتبقية:**
- مساحة HR mobile مصغرة (اعتمادات + دليل + إشعارات) بدل صفحة "ويب فقط".

**بوابة الخروج:** دورة رواتب تجريبية كاملة على Staging ببيانات 20 موظفًا وهميًا تطابق حسابًا يدويًا 100%، ودورة إجازة كاملة (طلب → اعتماد → خصم رصيد → ترحيل سنوي) مثبتة بـ pgTAP.

### المرحلة 3 — الوحدات المكملة (حسب المواصفة V8 Phase 3–4) 🟢

بالترتيب حسب القيمة:

### قواعد تنفيذ ملزمة طوال الخطة

1. **كل ميزة = Migration + pgTAP + اختبار واجهة + Evidence** — لا استثناء.
2. لا تعديل Migration مطبقة؛ Migration جديدة دائمًا (القاعدة الحالية، تبقى).
3. كل قرار حساس خادمي (RPC/Edge) — العميل عرض فقط (القاعدة الحالية، تبقى).
4. اختبارات ذات قيمة: منع اختبارات fromJson الشكلية من احتساب التغطية؛ المطلوب اختبارات سلوك (تدفق بصمة، حساب راتب، صلاحية مرفوضة).
5. تحديث `docs/runtime-evidence/` مع كل بوابة — الأرقام في README تُولّد آليًا لا تُكتب يدويًا.
